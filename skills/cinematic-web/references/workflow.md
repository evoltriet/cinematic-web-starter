# Agent Workflow

## 1. Discovery and durable truth

- Inputs: user goals, existing implementation, project context, constraints.
- Outputs: verified facts, assumptions, audience, primary action, first-viewport promise.
- Stop when: identity, authority, source rights, or stable interfaces are materially unclear.
- Context update: project context and assumptions ledger.
- Accept when: facts and assumptions are visibly separate.

## 2. Experience contract

- Inputs: discovery output and content inventory.
- Outputs: mobile-first chapter order, unique IDs, one job and one motion mode per chapter.
- Stop when: the primary action or semantic reading order is unresolved.
- Context update: config and experience plan.
- Accept when: the experience remains complete without decorative motion.

## 3. Art direction and tokens

- Inputs: cultural or product anchors, references, accessibility needs.
- Outputs: exact color, type, spacing, geometry, texture, depth, motion, and anti-pattern rules.
- Stop when: references risk copying, cultural flattening, or unreadable contrast.
- Context update: design context.
- Accept when: a reviewer can distinguish the direction from a generic landing page.

## 4. Responsive asset plan

- Inputs: chapter composition and configured budgets.
- Outputs: inventory, responsive variants, crop intent, formats, load priority, provenance.
- Stop when: rights, source, dimensions, or first-load cost are unknown.
- Context update: asset plan and assumptions.
- Accept when: desktop and mobile each have an intentional composition.

## 5. Motion selection

- Inputs: chapter job and design language.
- Outputs: static, reveal, triggered passage, or local scroll story with duration and fallback.
- Stop when: a global scene or motion-only meaning is proposed.
- Context update: config, experience plan, and documented exceptions.
- Accept when: motion adds hierarchy or continuity and remains bounded.

## 6. Semantic implementation

- Inputs: approved plans and stable interfaces.
- Outputs: semantic HTML, keyboard controls, focus states, reduced-motion result, then decoration.
- Stop when: core content is hidden by timing, hover, or JavaScript state.
- Context update: current implementation and interface notes.
- Accept when: the page works by keyboard and with animation disabled.

## 7. QA

- Inputs: built output, configured budgets, browser matrix.
- Outputs: structural, responsive, accessibility, performance, privacy, and interaction evidence.
- Stop when: any required gate fails or a budget exception lacks approval.
- Context update: QA report.
- Accept when: automated checks pass and human visual review is recorded.

## 8. Release

- Inputs: approved QA evidence and release scope.
- Outputs: context updates, migration notes, release notes, published artifact.
- Stop when: release authority, privacy scan, or rollback path is missing.
- Context update: project context, changelog, QA report.
- Accept when: published behavior matches the validated commit.
